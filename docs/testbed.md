# 준비 상태와 실행 경계

## 준비 상태

시나리오별로 `READY / BLOCKED / UNKNOWN`을 표시한다. 각 관측에는 환경 별칭, 관측 시각·유효 기한, 사용한 어댑터 버전, 이유 코드와 증거 참조가 필요하다. 이는 테스트 시작 준비 상태이며 보안 게이트 PASS나 컷오버 승인이 아니다. 시작 직전에 서버가 현재 권한·대상·잠금·필수 조건을 재검사한다.

| 범위 | 확인 항목 |
|---|---|
| 공통 | AWS/RKE2 API 도달성, 인증·필요 권한, 노드/CNI/PSA, Pod·Job, 리소스 여유, 해당 버전과 환경 등록 |
| DB 시험 | 두 DB·PgBouncer의 TLS·연결·제어 권한, 왕복 복제 경로·지연, 스키마·무결성 입력, 현재 쓰기 소유권, 실행 기록 저장소, 승인·게이트 연결 |
| 리허설 | namespace 한정 권한, NetworkPolicy 실측, PSA·quota, OpenBao/SeaweedFS 시험 입력, broker·검증 Job, 이미지 접근, UID 기준 정리 가능 여부 |

관측만 하는 점검과 실제 Pod 생성·접속 거부 시험 같은 능동 점검을 구분한다. 최초 연결은 읽기 전용으로 시작하고 능동 점검은 전용 자원과 명시한 시나리오에서 수행한다. 오래된 관측과 접근 오류는 UNKNOWN이다. 알려진 실패는 BLOCKED다.

## 실행 경로

웹 → 인증된 테스트 제어 서버 → 기존 플랫폼 승인·실행 경로 → 실제 AWS/RKE2 → 이벤트·영수증·측정값 저장 → 웹 조회.

실행 요청은 대상·시나리오·고정 플랫폼 SHA/이미지 digest·멱등 키에 결속한다. platform plan/command/run ID는 원본 값을 보존하고 테스트 실행 ID와 연결한다. 동일 DB·복제 경로는 기존 플랫폼 잠금을 공유해야 하며 웹 프로세스의 메모리 잠금만 사용하지 않는다. 서버 재시작과 응답 유실은 원본 상태 조회로 복구한다. 조회만으로 실행을 재제출하지 않는다.

DB 화면에는 현재 쓰기 소유권, 쓰기 차단/재개, 복제 barrier·무결성 비교, 단계 시간, SAFE_HOLD, failback을 보여 준다. AI 화면에는 제안·시도·차단 기록, AI 공간과 독립 채점 공간, Job·Pod UID, 검증 결과, namespace 정리 확인을 보여 준다. 알려지지 않은 값은 미확인으로 표시하고 애니메이션으로 실측을 대신하지 않는다.

## 안전한 실험

기본 대상은 명시적으로 할당한 전용 테스트 DB·복제·스토리지·namespace다. 네임스페이스 격리로 공유 노드·CNI·스토리지·네트워크 단절의 영향을 격리할 수 있다고 가정하지 않는다. 클러스터 전체나 공유 복제 경로에 대한 장애 시험은 별도 자원 또는 영향 범위 합의가 필요하다.

중단은 요청 접수, 실행기 중단 가능 여부, 실제 종료, 자원 정리 확인을 구분한다. 컷오버 중간에 UI 중단 버튼으로 쓰기를 강제로 열지 않는다. 정리에는 원본 run·namespace UID를 사용하고 다른 실행의 자원을 지우지 않는다. 복구 불명은 SAFE_HOLD 또는 사람 확인으로 유지한다.

회차마다 원측정값, 실패·유실·중복, 코드·이미지 버전, 대상 별칭, 시각, 기대 결과·실제 결과를 남긴다. 비공개 원본과 공개용 요약을 분리하고 공개 증빙 검사를 거친다. 재현·비교 화면도 기존 판정 결과를 소비하며 별도 판정기를 만들지 않는다.
