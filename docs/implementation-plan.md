# 구현 순서와 완료 기준

이 목록은 테스트베드 자체의 작업 계획이다. 플랫폼 공식 태스크 상태를 대체하지 않는다. 초기 문서 외의 구현은 아직 없다.

## 1. 플랫폼 기준과 접속 조사

- [ ] 최신 AGENTS·개발·보안·CI·계약과 담당 이슈를 읽고 고정 실행 SHA의 계약과 차이를 확인한다.
- [ ] 플랫폼 프런트엔드·서버·테스트 도구를 재사용할 구성과 모듈 이전 경로를 정한다.
- [ ] 실환경 API/실행기 버전과 사람·서버의 읽기·실행 권한을 값 노출 없이 확인한다.
- [ ] 전용 테스트 자원, 공유 자원, 현재 수행 가능한 시나리오를 식별한다.

완료 기준: 미연결·권한 부족을 포함한 연결 목록과 구현 범위가 문서화된다. 기존 자원 변경 없이 진행할 수 있다.

## 2. 읽기 전용 준비 상태와 관측 화면

- [ ] 인증된 서버에서 환경별·시나리오별 준비 상태와 근거·만료를 반환한다.
- [ ] 웹에서 AWS/RKE2·DB/복제·리허설 준비 상태를 확인한다.
- [ ] 기존 실행의 진행과 원본 ID·측정값을 조회한다. 연결되지 않은 데이터는 미확인으로 표시한다.

완료 기준: 실제 읽기 관측을 웹에서 확인하고, 권한 거부·오래된 관측·연결 실패를 정상으로 표시하지 않는다. 조회 시 실행 요청은 0건이다.

## 3. 리허설 실환경 실행

- [ ] 기존 T10/T15/T38 경로에 시나리오 요청을 연결하고 서버 재검사·멱등성과 원본 run ID를 유지한다.
- [ ] 전용 namespace에서 격리 시험·Job 실행·검증·UID 정리를 시각화한다.
- [ ] T42가 실제 연결된 버전에서만 AI 직접 시험을 활성화한다. 제안 검증과 AI 직접 실행을 구분한다.

완료 기준: 웹에서 시작한 실제 실행이 원본 영수증과 결속되고 실패·UNKNOWN·정리 실패도 화면에서 구분된다. 미완료 제품 템플릿을 완료로 표시하지 않는다.

## 4. DB 전환·복귀 실환경 실행

- [ ] 전용 DB 경로에서 기존 승인·게이트·Executor 잠금을 연결한다.
- [ ] 무부하 컷오버·failback, ABORT_PRE_WRITE·SAFE_HOLD를 확인한다.
- [ ] T18 부하 연결 후 5회 원측정·중앙값·최댓값과 유실·중복·실패를 표시한다.

완료 기준: 웹 요청에서 실제 명령과 측정 결과까지 추적되며 응답 유실·재시작에도 이중 실행이나 임의 쓰기 재개가 없다. 공유 환경 시험은 별도 범위 확인을 거친다.

## 5. 고도화와 비교

- [ ] 후보 SHA/digest별 시나리오·측정·증빙을 비교한다.
- [ ] 영향 범위가 확보된 환경에서 장애 주입과 중단·정리·복구 경로를 검증한다.
- [ ] 플랫폼 이전 단위와 의존성·테스트·출처를 정리한다.

완료 기준: 플랫폼 브랜치 수정 없이 후보를 시험할 수 있고 검증한 모듈을 플랫폼 PR로 옮길 수 있다.
